# Technical Specification: Modular Output Generation System (v4)

This specification details the refactoring of `data2prompt` to support multiple output formats (Markdown and XML), strictly following the Repomix pattern and ensuring high-fidelity representation of data science assets.

## 1. New Module: `src/data2prompt/output.py`

A new module will be created to encapsulate output generation logic, following the Modular Functional Orchestration (MFO) pattern.

### Class Structure

```python
from abc import ABC, abstractmethod
from typing import List, Dict, Any
from pathlib import Path
from .constants import (
    TAG_DIRECTORY_STRUCTURE,
    TAG_FILES,
    TAG_FILE,
    TAG_CONTENT,
    SYSTEM_INSTRUCTIONS_MARKDOWN,
    SYSTEM_INSTRUCTIONS_XML,
    GENERATION_FLAG
)
from .utils import get_dynamic_wrapper

class OutputGenerator(ABC):
    @abstractmethod
    def generate(self, 
                 project_name: str, 
                 tree_text: str, 
                 files_data: List[Dict[str, Any]], 
                 stats: Dict[str, Any],
                 total_tokens: int,
                 token_method: str) -> str:
        pass

class MarkdownGenerator(OutputGenerator):
    def generate(self, ...) -> str:
        # Implementation for Pure Markdown format
        # Uses ## File: {path} headers
        # CONSISTENCY: Every file (except notebooks) uses get_dynamic_wrapper
        pass

class XMLGenerator(OutputGenerator):
    def generate(self, ...) -> str:
        # Implementation for XML format
        # Wraps everything in <project_context>
        # Uses <file path="{path}"> tags
        pass

def get_generator(format_type: str) -> OutputGenerator:
    if format_type.lower() == 'markdown':
        return MarkdownGenerator()
    return XMLGenerator()
```

## 2. Output Templates

### Markdown Format (Pure Markdown)
```markdown
<!-- THIS MARKDOWN WAS GENERATED BY DATA2PROMPT -->
# Project Context: {project_name}

{SYSTEM_INSTRUCTIONS_MARKDOWN}

> Generated on: {timestamp}
> Tokens: {total_tokens} (est. via {token_method})

# Directory Structure
```text
{tree_text}
```

# Files

This section contains the contents of the repository's files.

## File: {relative_path}
{dynamic_wrapper}{lang}
{content}
{dynamic_wrapper}

... (For Notebooks) ...

## File: {relative_path}
<content cell_number="{n}" cell_type="{type}" file_path="{relative_path}">
{cell_content}
</content>
...
```

### XML Format (Repomix-inspired)
```xml
<!-- THIS MARKDOWN WAS GENERATED BY DATA2PROMPT -->
<project_context name="{project_name}">

{SYSTEM_INSTRUCTIONS_XML}

<metadata>
    <generated_on>{timestamp}</generated_on>
    <total_tokens method="{token_method}">{total_tokens}</total_tokens>
</metadata>

<{TAG_DIRECTORY_STRUCTURE}>
{tree_text}
</{TAG_DIRECTORY_STRUCTURE}>

<{TAG_FILES}>
This section contains the contents of the repository's files.

<file path="{relative_path}">
{content}
</file>

... (For Notebooks) ...

<file path="{relative_path}">
<content cell_number="{n}" cell_type="{type}" file_path="{relative_path}">
{cell_content}
</content>
...
</file>

</{TAG_FILES}>
</project_context>
```

## 3. Updated Constants (`src/data2prompt/constants.py`)

```python
# Updated Tags
TAG_DIRECTORY_STRUCTURE = "directory_structure"
TAG_FILES = "files"
TAG_FILE = "file"
TAG_CONTENT = "content" # Used for notebook cells

# Refactored System Instructions (Repomix Style)
SYSTEM_INSTRUCTIONS_MARKDOWN = """This document is a structured representation of a codebase and data schema. It is designed to be consumed by a Large Language Model.
The output is organized into sections:
1. Directory Structure: A visual tree of the project.
2. Files: The content of each file, clearly labeled with its path using '## File: {path}' headers.
For all standard files, content is wrapped in markdown code blocks using dynamic backtick depth to ensure robust nesting.
For notebooks, individual cells are encapsulated in <content> tags with metadata attributes (cell_number, cell_type, file_path) to maintain execution context."""

SYSTEM_INSTRUCTIONS_XML = """This document is a structured representation of a codebase and data schema. It is designed to be consumed by a Large Language Model.
The output is organized into XML tags:
1. <directory_structure>: A visual tree of the project.
2. <files>: Contains the repository's files.
3. <file>: Represents a single file with a 'path' attribute.
4. <content>: Used within notebooks to encapsulate cells with 'cell_number', 'cell_type', and 'file_path' attributes."""
```

## 4. Notebook Parser Refactoring (`src/data2prompt/parsers.py`)

The `process_notebook` function will be updated to use the new `<content>` tag structure:
- `cell_number`: 1-based index.
- `cell_type`: 'code' or 'markdown'.
- `file_path`: The relative path of the notebook.

## 5. CLI Integration (`src/data2prompt/cli.py`)

- Add `--format` argument to `setup_cli`.
- Default value: `xml`.
- Update `Config` dataclass to include `format: str`.

## 6. Main Orchestration (`src/data2prompt/main.py`)

- Import `get_generator` from `.output`.
- In `run_packager`, instantiate the appropriate generator based on `config.format`.
- Collect all necessary data (tree, processed files, stats) into a structured format.
- Call `generator.generate(...)` to get the final string.
- Write the result to `config.output`.
